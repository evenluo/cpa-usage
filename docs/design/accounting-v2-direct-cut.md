## Contract

The maintainer approved one direct cut with no old-producer support, dual metric semantics, or unpublished intermediate upgrade paths. The supported producer is the Accounting v2 queue contract pinned to CPA v7.2.152 c76dfd4e0edabab9000628b1560ab8ab379eadb8. Product features from Parent #140 remain in scope.

- Canonical v2 is the only source of token metrics throughout KPI, trend, contributors, analysis, overview, model mappings, Request Evidence, CSV and Output TPS. Never substitute the producer's old token scalars. Output TPS uses canonical output total (including reasoning) / (latency - TTFT), only for complete-quality generating streaming attempts with valid positive timing/output.
- Preserve historical raw events and operator configuration without rewriting facts. Historical attempt counts/status/timing remain observations; missing canonical token facts remain unavailable and never acquire inferred values. Historical scalar columns are archival data, not an active alternate metric path. No history deletion, second history UI, compatibility toggle, or timestamp-based decoder switch.
- New queue messages require accounting/schema version 2, all canonical buckets, one of complete/inconsistent/unclassified, correct nonnegative bounded sums, and explicit generate/stream booleans. Unsupported/malformed messages are isolated using the existing observable inbox decode_failed lifecycle; no legacy-success fallback or malformed-field sentinel protocol. Excluded sensitive fields must never enter the inbox. Replay and inbox-row attempt identity remain deterministic. Existing pre-effect-only Redis transport protection remains. Before the one-time schema cut, the published consumer must finish all local pending/process_failed inbox rows; migration rejects a nonempty processable inbox without changing its data. This permits removal of the historical queue-key event-identity adapter.
- The repository owns one canonical metric interpretation. Absence in historical rows and invalid persisted facts are unavailable, never zero evidence. Canonical quality is independent of structural validity. Keep only valid/absent/invalid availability categories; remove producer-version/missing/malformed compatibility state matrices.
- Keep local three-rate price configuration and estimates. For complete canonical observations only: prompt rate applies to uncached input plus cache-write input, cache rate to cache-read input, completion rate to canonical total output including reasoning. This is the explicitly defined local estimate, not upstream billing. Missing canonical data, non-complete quality or missing required pricing cannot yield a complete Cost claim. A complete zero-token attempt has known zero Cost without a price; an aggregate mixing known and unknown costs is partial. Hourly rollups retain the complete-zero count needed to preserve this distinction. Do not alter the unrelated pricing scripts or configuration.
- Upgrade only from published main to the integrated binary. Existing raw rows become canonical-absent. Initialize historical rollup accounting absence from request_count and canonical sums/other new counters to zero within the migration; preserve backfill lifecycle/checkpoint. No new full-history backfill or coverage reset. Existing rollup rebuilds for newly inserted events remain owned by the current transaction/runner.
- Every events selection uses one diagnostic selection validation rule. Preserve legitimate selected-window browsing, but remove parameter-dependent old validation and pagination aliases where superseded. CSV retains its explicit fixed 24h window and row cap.
- Real partial upstream reads, optional quota observations, quality, source timestamps and explicit failures remain truthful runtime outcomes. No all-or-nothing protocol, retry framework, new worker/cache, or provider fallback is added.
